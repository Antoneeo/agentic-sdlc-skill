# Course Creator — beta

`course-creator` helps an AI agent create a course for a defined learner. It maps what the learner already knows, orders concepts by prerequisite, writes explanations in progressive modules, and links factual statements to reopenable sources. Independent fresh learner agents can expose confusing steps; their results are diagnostic. The course is labeled **efficacy not verified** until enough evidence from real learners supports a narrower claim.

The package is the fourth lens of the Agentic SDLC family. It uses the shared `ai_docs/` project memory and governance. Version 0.1.0-beta.4 supports Standalone mode. This is an experimental beta: the authoring method and artifact contracts may change; human learning efficacy has not been established. Its course artifacts remain readable without the skill. Each new course keeps a verbatim, append-only record of the requester's own words and decisions in `audit/requests/`, cited by the analysis and checked by its reviews.

## What's new in 0.1.0-beta.22

**The team is asked once, at the start, and kept where every session finds it.** At the first new course (L3) of a project the agent asks you four questions: who is in the team, what stays with you, what each member decides alone and to whom it reports, and how work and reports pass. It keeps the answer in a `## Team` section of `ai_docs/README.md`, so a later session, a session another one started and a resumed one all find it, and roles are no longer settled while the work is under way. One word accepts the default: one agent, and you keep your own decisions and the reserved approvals. A smaller change is never asked (F-098).

**A design no longer drifts stricter than the reason it was written for.** Every restriction an L3 course design writes now names its source (a clause of your Vision, your own words in the request record, or a threat) and goes no further than that source asks. One that goes further is tightened back or brought to you, and one that takes away something your Vision promises enters the design only if you choose it. The independent design review checks this, and a second failed review of the same kind sends the agent back to the restriction's source instead of into another round of fixes (F-099).

**When new work opens, you see what is already open.** In the message that opens a new L3 course, the agent copies the rows of the workstream registry (`ai_docs/audit/handoff.md`) as they are written, workstream, status and next step, adding and cutting nothing, and goes on in the same message. If your request belongs to an open workstream, it resumes that one instead of opening a second (F-097).

**The checks say what they measure.** `check` now ends with a line stating that it verifies the form of the documents, not whether their sentences are still true, so a CLEAN result is no longer read as "the documents are correct". `validate` and `index` name a workstream file whose status says the work is closed, since closing means deleting that file. An agent resuming from a summary is told to re-read the unit's request record and Vision before acting, and an edited guide is re-read whole and its outdated sentences rewritten, not patched with a change-log row (F-096).

#### What to do

Everyone who has this package installed: run `npm install -g @antoneeo/course-creator@latest`, then `course-creator-install-skill`, and restart your agent sessions. The install step copies the updated doctrine, `team.md` and the validator into your skills directory; sessions already open keep the old ones until restarted. At the first new course (L3) of each project, expect the four team questions: answer them, or reply with one word to accept the default. An existing project may see a new note from `validate`, never a failure: a workstream file (`audit/HANDOFF_*.md`) whose `status:` says DONE, COMPLETED or CANCELLED, which you delete once the work is really closed, after moving what is still worth reading elsewhere, or keep with an open status and a `next:` if it still waits on you; then run `index`. To check it worked, run `npm ls -g @antoneeo/course-creator` and look for 0.1.0-beta.22.

## Install and initialize

```sh
npm install -g @antoneeo/course-creator
course-creator-install-skill
cd YOUR_PROJECT
course-creator-init
```

The installer detects Claude Code, Gemini CLI, Codex and Google Antigravity. Initialization creates absent `ai_docs/` files and a project protocol pointer; it does not overwrite existing project documents. Use `python <skill_dir>/scripts/sdlc_check.py check --root .` to validate the shared SDLC and course structures. `check` states what it covers: after its verdict a `[scope]` line says it checks the form of the documents, not whether their sentences are still true; and `validate`/`index` name a workstream file whose own status declares the work closed. (`validate` also names an analysis in progress that no workstream file names, in the other domains of a shared project; never a course analysis, whose workstream file is owed for concurrent work only.)

**The team, asked once**: at the first new course (L3) of a project the agent asks the owner four questions — who is in the team, what stays with them, what each member decides alone and to whom it reports, how work and reports pass — and keeps the answer in a `## Team` section of the reading guide, where a later session, a session another started and a resumed one all find it. One word accepts the default (one agent; the owner keeps their own decisions and the reserved approvals). The skill asks and prescribes no team shape; a smaller change is never asked (`team.md`).

**Docs site** (`scripts/docs_site.py --root <project> [--open] [--zip <file>]`): a static, offline, read-only website of what the agent reads in the project — reading guide, Vision, rules, documents, open work with each next step, courses and, with a knowledge base, the topic map, each fact with its exact source passage, and the source documents. Written to `.docs-site/` (added to `.gitignore` on the first run), outside `ai_docs/`; nothing is ranked or recommended.

Using the skill in your own project carries no obligation to publish your course or its sources. See [LICENSE](LICENSE) for the software terms and [NOTICE](NOTICE) for attribution.

## Primary course output

New courses deliver a complete textual source for every slide (`SLIDE_CONTENT.md`), with exact learner copy, full explanations, examples, visual contents, transitions and answers. PPTX and other renderings are optional. Explicit non-slide requests retain a complete textual source for their units. Every course must show distinguishable value for its audience through an explanatory contribution and a transfer task; structure or simulated success does not establish human efficacy. See `skills/course-creator/slide_content.md`.

A course delivered by an instructor (`Delivery mode: instructor-led`) also ships `INSTRUCTOR_GUIDE.md`: what to prepare, the schedule, what to keep out of the learners' view, what to do when a live step fails, what to clean up afterwards, and the list of every material the delivery needs, wherever it is in the project, checked to exist. `course_check` refuses an instructor-led course without the guide, or with a guide that does not follow the template in `templates.md`. An existing instructor-led course therefore fails `check` until its guide is written to that template. In any course with a content contract it also refuses a line that names the course with a dotted version other than the declared `Course version`.

Course design now uses outcome-first evidence, teaching/assessment alignment, visible worked reasoning, proportionate support, cognitive-load management and retrieval opportunities. `learning_design.md` records the pedagogical sources and the source-informed semantic review rubric; a locator table or structural PASS is not proof of learning.
