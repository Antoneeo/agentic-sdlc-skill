## Notes
- **F-024 kb Knowledge Method — four reviews before a line of code, 70 findings, 68 real.** Three lenses attacked the design *spec* while it was still a scratch document and before any ANALYSIS existed (concurrency & failure modes; the knowledge model itself; fit with the family), then the design gate ran on the ANALYSIS the three had shaped. All four FAILED, and the architecture survived all four — what did not survive was the schema and the arithmetic under it. **The root defect, found independently by two lenses:** the design declared "the claim, not the document, is the unit of reconciliation" and then stored provenance per *node*, so every per-claim attribute was destroyed at write time and the reconciliation ladder was unrunnable against its own output. The repair — a claim table with stable ids, and edges *derived* from it rather than hand-written — also closed two further findings at once (retrieval recall holes no check could detect, and the false claim that parallel writers touch disjoint nodes: resolving a hand-written back-link means writing into another agent's file). **The design gate's sharpest finding was an architect-pass failure of mine:** the capability ruled MISSING — "hold an assertion with its own provenance" — is already half-owned by `mkt_check.py#load_ledger/run_ledger`, registered as the portable check `marketing.ledger` and advertising itself for import by other domains; the ledger row said "No owner" after a grep that would have surfaced it. Component extracted as F-025 `ANALYSIS_claim_ledger.md`, which is also what `architect.md` §4 requires of a component with two consumers and its own data model. Other repairs worth recording because each was a rule that *looked* obeyed: the claim id keyed on claim text defeated the very idempotency it was introduced to provide (an LLM re-extraction paraphrases, so the hash moves); content-addressing `corpus/given/` made the freshness use-case unreachable by construction, because bytes that never change can never drift — restated as supersession; `cmd_stale` cannot see anything outside `reference/GUIDE_*.md`, so "reuse the freshness engine" was false and the detector is new code; there is no subparser hook in the spine, so the overlay must *intercept* `index`/`validate`/`check` as `mkt_check.py` does, and must name its functions `kb_*` or `from sdlc_core import *` silently rebinds what three SHARED batteries call as `sc.cmd_index`; a single `parent:` let the router satisfy "query the graph before declaring MISSING" while descending the branch the topic was not under; and the subtree coverage distribution was the readiness board the Vision's own amendment record names as the forbidden capability. **Two findings were rejected, and the reason is a process lesson:** the reviewer read `templates.md` and `handoff.md` *after* this session had already repaired them, and reported the ANALYSIS's account of the prior state as fabricated. Do not run a review against a tree you are still editing.
