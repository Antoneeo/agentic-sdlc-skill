# Admission rulings — the precedent ledger

**Why this file exists.** A prose gate re-interpreted from scratch on every proposal has
no memory: a rejected capability returns reworded and the game restarts. Here the game
does not restart. A capability's identity is **the question it answers / the effect it
has in the delivered system — never its vocabulary**: a restatement is a paraphrase,
and a paraphrase lands on the same row, which already carries its verdict.

**The procedure** (it precedes the prose, `project_vision.md` §The admission test):

1. **Place** the proposal against this table: does it answer the same question as a
   row? Semantic judgement, same discipline as kb's taxonomy pass.
2. **EXISTS → the row's verdict applies.** To claim otherwise, write the **distinction
   line** — "it answers a different question because …" — falsifiable, on the record.
   If the distinction line cannot be written, it is the same capability (the sibling
   rule). Silent re-interpretation is not a path that exists.
3. **MISSING → the prose rules once**, and the verdict becomes a new row. A proposal
   matching both an ADMIT and a REJECT row is **CONTESTED → the owner rules, with the
   basis recorded**. The machine never decides.

A working bypass is not a Vision failure to rewrite around — it is a new row. The
ledger only grows; rows are superseded by an owner ruling, never deleted.
