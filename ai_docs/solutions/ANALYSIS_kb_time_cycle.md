# ANALYSIS: KB Time Cycle (F-044)

## Feature Vision

`VISION_kb_second_brain.md` (APPROVED), unit 3 — verbatim charter: "Staleness per
claim, supersede esplicito, invalidation cascade sulle catene, consolidamento
periodico. Progettato per ultimo, sui DATI che le prime due unita' generano."
Success signals served: "Nessun claim superseded citato senza che il supersede sia
visibile"; "Alla caduta di un claim, l'elenco dei derivati da rivedere e' prodotto
meccanicamente." Non-goals that bind: no semantic contradiction detection, no
external infra, no per-turn graph hammering, and (handoff watch-out)
"consolidamento periodico" must never become a standing ritual.

Evidence dossier: the four 2026-08-28 field data in `HANDOFF_kb_time_cycle.md` —
the strongest being the 12-document post-mortem that named this cascade UNPROMPTED
as the answer to its own failure.

## Use Cases / User Needs

- **UC-A (dead truth cited with confidence).** A living document — a solutions
  ANALYSIS, a guide, or another TOPIC's prose — cites claim `3f2a...` which a
  later ruling superseded. Today nothing surfaces it; the vision demands the
  supersede be VISIBLE wherever the claim is cited.
- **UC-B (the fall reaches the derivatives).** A newer source version supersedes a
  `given/` artifact. UC4 already warns claims resting on it directly; the notes
  built transitively on it (`derived_from` chains, F-035) stay silently standing.
- **UC-C (what ages, at what rhythm).** Claims carry `valid: until <date>` windows
  that no check ever evaluates against today — an expired claim is silently live.
- **UC-D (the consolidation moment).** After a supersession, the practitioner
  needs the mechanical revision worklist (which documents, which notes) without
  assembling it by hand — and a session must not open blind to it.

## Functional Spec

Owner ruling (elicitation 2026-08-28, all four confirmed): WARN not ERROR;
evaluate the existing `valid` window (no new column); command + orient line;
subagent grant session-wide.

One shared collector, `kb_time_cycle(docs)`, computes the three lists once and
feeds every surface (`check`/`graph`/`corpus` warn streams, `stale`, orient) —
never parallel scans.

**FS-1 — Citation staleness (the WARN).** For every ledger row whose `state` is
`SUPERSEDED <succ>[, <succ>...]` (the grammar accepts a comma list of
successors): a living document that contains the superseded id but NOT **every**
successor id gets one warning per (document, id) pair, naming the missing
successors — `"<doc>: cites <id>, superseded by <succs> — successor(s) <missing>
not named; revise per the Revision doctrine"`. ALL successors must be visible to
clear: a claim split into two rows is only honestly superseded when the reader
can see both halves of what replaced it. The condition is the vision sentence
made mechanical, and it self-clears two doctrine-conform ways: an F-043
full-rewrite that replaces the id, or an append-only Diary correction entry that
names the successors (history never rewritten). Supersession chains need no
special case: a successor row that is itself superseded is in the superseded set
and warns pairwise on its own.
  - **Id matching is hex-bounded, case-tolerant on the run:** ids are bare
    lowercase 12-hex; a match counts only when not embedded in a longer hex run
    — `(?<![0-9a-fA-F])<id>(?![0-9a-fA-F])` — or a git hash sharing a substring
    would false-positive. The successor-visibility test uses the same boundary.
    Ids are validated 12-hex before pattern assembly (no user text reaches the
    regex compiler unescaped).
  - **Scan set (living documents only):** every `*.md` under the docs root —
    `topics/*.md` INCLUDED, because another topic's prose citing a fallen claim
    is exactly UC-A on the highest-traffic reading surface (recall descends
    into topics), and the OWNING topic file self-clears by construction: its
    own state cell `SUPERSEDED <succ>` puts every successor id in the same
    document. Excluded: (a) generated files, identified by the spine's own
    generated-file predicate (`GENERATED by \S+ index - do not edit by hand`),
    never by filename and never by a kb-only literal — a registry generated by
    a sibling lens's entry point is just as generated; this covers every
    `INDEX.md`, `strategic/features_history.md` and the generated
    `audit/handoff.md` registry, whose text can echo a claim id from an
    authored source and would otherwise warn unfixably-in-place; (b)
    `corpus/given/` and its sidecars — remedy-free surfaces: `given/` bytes
    are digest-pinned after ingest, and a sidecar's only legal edit advances
    `extracted_through:`; (c) any
    document whose frontmatter `status:` is SUPERSEDED — tombstones are
    history. `corpus/notes/` IS scanned: a note is a living record and its
    remedy is document-level supersession or a correction note, never an
    in-place rewrite of history.
  - Severity and placement: WARN, printed in the kb claims-check stream (the
    same `[warn]` stream `kb_check_claims` feeds, so `check` and `graph` both
    surface it) and listed in the `stale` view. Never an error; rc semantics
    unchanged.

**FS-2 — EXPIRED is computed, never written.** A row whose `valid` parses to a
window with `until <= today` (half-open — `until X` means the claim stopped
applying ON X, matching `kb_scopes_overlap`'s exclusive `until`) is EXPIRED
**in reports only**: the `stale` view and the orient count. It is NOT a
state-cell transition (the machine never decides — reconciliation owns state
writes), NOT a check warning (expiry is honest self-declaration, not an error;
there is no successor whose naming could clear it, so a warn would be an
unfixable ratchet). `if <cond>` scopes stay undecidable and are never expired;
a future `from` is skipped silently. The one doctrine line ("expiry is computed
at report time, never written into `state`") lives in `templates.md` beside the
claim schema it qualifies — the schema's single home — not in `distillation.md`.

**FS-3 — Transitive chain cascade.** Extend UC4 from direct to transitive: for
every `given/` artifact named in some sidecar's `supersedes:`, walk the reverse
`derived_from` edges and list every transitively-derived document that is not
itself `status: SUPERSEDED`: `"corpus/notes/<n>: derives (via <chain>) from
<artifact>, which a newer version supersedes — re-derive from the successor or
supersede the note"`. Reported in the `stale` view and counted by orient; in
`check` it surfaces beside UC4, in the corpus warn stream, at the same warning
severity.
  - **The edge graph covers sidecars too.** Reverse edges are built from BOTH
    `derived_from` carriers: note frontmatter AND `given/*.meta.md` sidecars
    (the F-035 OCR/translation class — an extraction whose sidecar says
    `derived_from: scan.png`). A chain note → given/extract → (sidecar edge) →
    given/original therefore reaches the fallen original; derived `given/`
    artifacts are listed alongside notes when they sit on a superseded ground.
  - **Edge parsing, pinned:** `derived_from` accepts a single value or the
    YAML-ish inline list `[a, b]` (real usage in the eval fixtures); entries
    may be YAML-quoted (single or double — paths with spaces force quoting)
    and quotes are stripped before resolution, per the field-reported corpus
    quoting defect (2026-08-28: 102 false dangling-pointer warns on quoted
    `original_path:` values); each entry resolves docs-root-relative when it
    contains `/`, else it is tried as `corpus/notes/<name>` then
    `corpus/given/<name>`.
  - **Dangling edges are surfaced, not skipped — corpus-wide and standing.**
    No existing check resolves `derived_from` targets (today only presence is
    validated), so a dangling entry would make the cascade silently stop while
    claiming coverage. The collector therefore emits a walkability warning for
    ANY `derived_from` entry (note or sidecar) that resolves to nothing —
    `"...: derived_from <x> resolves to nothing — the chain is not walkable"`
    — in the corpus warn stream, whether or not any supersession exists: a
    chain must be walkable BEFORE anything falls for the cascade promise to
    hold. This is a new check, not a duplication: the existing
    dangling-reference errors cover claim `source` cells and sidecar originals
    only.
  - Cycle-safe (visited set); each document listed once per superseded
    artifact.

**FS-4 — The consolidation view: intercept `stale`.** Add `stale` to the kb
overlay's `INTERCEPTED` set. The kb handler mirrors ALL the spine flags the
command carries today — `--root`, `--docs-dir` AND `--hybrid` — runs the
spine's `cmd_stale(root, hybrid=...)` first (its output and exit semantics
preserved, `--hybrid` passed through, so `stale --hybrid` keeps its promised
guide-drift behavior instead of dying as an argparse usage error), then appends
a `## claims` section with the three lists: superseded-cited (doc → id →
missing successors), EXPIRED (id, topic, window end, plus "still cited by"
documents as information), and chain-cascade notes. A nonempty `## claims`
section NEVER moves `stale`'s rc — the spine's verdict stands. Note: spine
`cmd_check` calls spine `cmd_stale` internally, so kb `check` does NOT print
the `## claims` section; `check` carries the FS-1/FS-3 warn lines instead
(placements pinned above), and ENFORCEMENT.md states this split explicitly.
Event-driven by construction: it runs when invoked — after recording a
supersession (doctrine, FS-6) or on demand. No new vocabulary: one staleness
door per lens.

**FS-5 — The orient count line.** In the kb orient append (after the note
recency line), one line, ONLY when at least one count is nonzero:
`"kb time: N docs cite superseded claims; M claims expired; K notes on
superseded sources — run sdlc_check.py stale"`. Silent when clean (distill
lesson: noise is failure one), fail-open like the recency line (nothing in it
may break orient). Cost, stated honestly: this is one full collector run at
session start — a real walk the recency probe does not do today — accepted as
the once-per-session event the consolidation needs; it is NOT per-turn, and the
collector is shared with `check`/`stale`, never re-implemented leaner here
(under-counting via a shortcut walk is the failure mode to refuse).

**FS-6 — Doctrine (the event, not a ritual).** `reconciliation.md` §2 gains the
post-supersession step: recording a supersession ends by running `stale`; the
lists are the revision worklist, worked per the Revision doctrine (one document
= one full re-read). SKILL.md closure phase gets one pointer line (run `stale`
at closure when the session recorded any supersession). ENFORCEMENT.md
documents the mechanics, severities, and the check/stale output split (FS-4).
The `remind` payload is NOT touched (per-prompt budget; this cycle is
event-driven, not per-turn). No text restates the F-043 canonical clause — the
once-only DRY pin binds every skill-dir `*.md` this unit edits.

## Interface Contract

- `sdlc_check.py stale [--root ...] [--docs-dir ...] [--hybrid]` — spine output
  and exit semantics first (hybrid passed through), then `## claims` (three
  lists, deterministic order: by path, then id; empty lists print nothing — a
  clean corpus adds zero lines; the section never changes rc).
- `sdlc_check.py check` — existing output plus FS-1 warnings in the claims
  warn stream and FS-3 warnings in the corpus warn stream; rc meaning
  unchanged (warnings never fail a check that would otherwise pass). No
  `## claims` section here.
- `sdlc_check.py orient` — existing output plus the FS-5 line when nonzero.
- Ledger schema, claim-id hashing (`path#locator#qty`), state grammar,
  `derived_from`, sidecars: ALL UNCHANGED. Zero migration for existing corpora.

## Security & Threat Model

No new input surface: the collector reads the same docs-root files the checks
already parse, with the same tolerant parsers. Ids are validated 12-hex before
any pattern assembly (no injection from document text into regexes). No
network, no state writes, no schema change. A hostile document cannot make the
collector write anything: it only reads and prints. Failure posture:
`stale`/`check` sections raise normally (they are checks); the orient line
alone is fail-open (a broken corpus must not break session start — F-041
posture).

quoted edge entries (paths with spaces), dangling `derived_from` entry with no
supersession anywhere (standing walkability warn, no crash).
